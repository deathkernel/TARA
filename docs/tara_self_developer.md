# TARA Self-Developer v1 (controlled autonomy)

## Scope and safety

The self-developer proposes changes only inside a separate Git worktree of the
TARA repository. It does not merge, push, publish releases, install packages,
or edit the original working tree. A user must inspect the report and diff and
manually integrate any accepted change.

The runner uses argument-vector subprocess calls with shell disabled. Every candidate runs `compileall` against `src`. If a Python source file under `src/` changes, the runner also runs the full `pytest -q` suite because regressions may be outside the changed file. If only test files change, it runs pytest against those changed test files. Git/compile checks and focused pytest commands keep a five-minute timeout; the complete suite has a separate three-hour default timeout because the recorded full suite can take over two hours. Captured output is bounded in reports.

To override the full-suite timeout in Windows CMD, set `TARA_SELF_DEVELOPER_FULL_TEST_TIMEOUT_SECONDS` to an integer from `60` through `86400` (24 hours) before starting the CLI. For example, `set TARA_SELF_DEVELOPER_FULL_TEST_TIMEOUT_SECONDS=14400` allows four hours. The setting applies only to the complete `python -m pytest -q` command; it does not extend Git, compile, or focused-test timeouts. Invalid values fail validation rather than silently falling back.

The patch gate rejects absolute paths, traversal, protected user artifacts,
dependency files, and workflow files. The protected paths include
checkpoints/, outputs/, data/conversation_v1.jsonl,
data/conversation_v1.jsonl.manifest.json, and test_voice.py.

A Git worktree is change isolation, not a hostile-code sandbox. This version
must only be used with a trusted local model and reviewed candidate patches.
Do not use it to execute arbitrary scripts generated by an untrusted model.

## Windows CMD

From the TARA repository root:

```bat
set TARA_LLM_BACKEND=ollama
set TARA_LLAMA_MODEL=llama3.2:3b
python -m src.self_developer_cli status
python -m src.self_developer_cli plan "Add a regression test for memory retrieval"
python -m src.self_developer_cli run "Add a regression test for memory retrieval"
python -m src.self_developer_cli report
```

Ollama must be running and the selected model must already be installed.
The status command does not need a model, but the CLI factory returns no
provider until TARA_LLM_BACKEND=ollama is set.

Reports and candidate worktrees are stored outside the repository under
%LOCALAPPDATA%\TARA\self-developer\. This avoids adding generated runtime
artifacts to the user's working tree. Candidate worktrees are retained for
inspection; review their diffs before any manual cleanup.

## Review and integration

1. Inspect the JSON report and candidate branch/worktree paths.
2. Review the candidate diff and the exact test output.
3. Run additional relevant tests manually if needed.
4. Only after approval, manually apply or cherry-pick accepted changes.
5. Never use git clean or git reset --hard in the original repository, and
   never integrate a candidate automatically.

## Current limitations

- Llama-generated patches are proposals, not trusted facts.
- Test success is necessary but not sufficient for correctness.
- This version does not support automatic commits, pushes, merges, dependency
  installation, or arbitrary shell execution.
- Failed runs retain their report and candidate worktree for diagnosis.
